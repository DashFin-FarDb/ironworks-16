# T35: Production & Consumption Stats Tracker (`src/machines/statsTracker.ts`)

Implemented `StatsTracker` and `createStatsTracker()` for cumulative and rolling 60-second (`STATS_WINDOW_TICKS = 3600` at 60 TPS) items/min tracking.

## Exports
- `STATS_WINDOW_SECONDS` (`60`), `STATS_WINDOW_TICKS` (`3600`)
- `StatsTrackerOptions`, `StatsTracker`, `createStatsTracker(options?)`

## Key Design & Edge Cases
- **Exact Tick-Level Rolling Window:** Uses a per-item coalesced tick deque (`(currentTick - windowTicks, currentTick]`) with incremental running sum and amortized O(1) compaction (`head > 256 && head * 2 >= length`). At the default 3,600-tick window, `producedPerMinute` / `consumedPerMinute` equals the exact integer rolling sum with zero floating-point drift; custom `windowTicks` scale via `(sum * 3600) / windowTicks`.
- **Canonical Determinism:** `getSnapshot(currentTick)` and `syncToWorld(world)` emit `ProductionStats.byItem` keys in canonical `ALL_ITEM_IDS` order. No `Date.now()` or `Math.random()`.
- **Integrations:**
  - `attachEventBus(eventBus)` subscribes to `itemProduced` events and returns an `Unsubscribe` handle.
  - `syncToWorld(world)` is designed for the `'stats'` tick phase, updating `world.stats` in-place.
  - `hydrateFromStats(stats, currentTick)` restores cumulative totals after `WorldState` deserialization (rolling windows start empty).
- **Fail-Closed:** Validates `ItemId` via `assertValidItemId` (`UnknownItemError`), and validates `count`, `tick`, and `windowTicks` as non-negative/positive integers (`SimulationError`). `count === 0` is a valid no-op.
