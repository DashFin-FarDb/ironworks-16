# T26: Assembler Mk1 (`src/machines/assemblerMk1.ts`)

Implemented the deterministic, headless, fail-closed `assembler_mk1` machine (75 kW, `<= 2` ingredients, crafting speed `0.5`).

## Exports
- Constants: `ASSEMBLER_MK1_POWER_DEMAND_KW = 75`, `ASSEMBLER_MK1_CRAFTING_SPEED = 0.5`, `ASSEMBLER_MK1_MAX_INGREDIENTS = 2`, `ASSEMBLER_MK1_INPUT_SLOTS = 2`, `ASSEMBLER_MK1_OUTPUT_SLOTS = 1`, `ASSEMBLER_MK1_FOOTPRINT = { width: 1, height: 1 }`.
- Functions: `createAssemblerMk1`, `canAssemblerMk1CraftRecipe`, `setAssemblerMk1Recipe`, `stepAssemblerMk1`, `tickAssemblerMk1`, `tickAllAssemblersMk1`.

## Key Design Choices & Edge Cases
- **Item Conservation & Serialization:** Because `AssemblerEntity` has no hidden `inProgress` buffer, ingredients are verified via `hasItems` each tick and atomically consumed (`consumeIngredients`) + outputs inserted (`insertItem`) on craft completion (`craftingProgress + 1e-9 >= recipe.craftingTicks`). Clearing or switching recipes resets `craftingProgress` and `active` without destroying items in `inputInventory` or `outputInventory`.
- **Fail-Closed Validation:** `setAssemblerMk1Recipe` and `stepAssemblerMk1` reject unknown recipes (`UnknownRecipeError`), non-assembling recipes (`INVALID_RECIPE_CATEGORY`), recipes with `> 2` ingredients (`TOO_MANY_INGREDIENTS`), locked recipes when `researchState` is provided (`RECIPE_LOCKED` on set; clean `recipe_locked` halt on step), and invalid power satisfaction (`INVALID_POWER_SATISFACTION`).
- **Input Slot Filtering:** By default (`applyInputFilters: true`), `setAssemblerMk1Recipe` sets per-slot filters on empty input slots to match `recipe.ingredients[i].itemId` so inserters cannot starve one ingredient by filling both slots with another.
- **Power & Backpressure:** Uses T18 `getEntityPowerSatisfaction` and `scaleMachineSpeed`. Zero power (`no_power`), missing ingredients (`missing_ingredients`), or full output (`output_full`) halt cleanly with `active = false` and zero progress. Emits `itemProduced` on `EventBus` upon completion. `tickAllAssemblersMk1` iterates in ascending `EntityId` order.
