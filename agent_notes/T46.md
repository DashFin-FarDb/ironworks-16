# T46: 160×160 Corner Minimap (`src/render/minimap.ts`)

## Key Design Choices
- **Dual API (Pure + Class Wrapper):** Exports pure functions (`computeMinimapRect`, `computeCameraViewportBox`, `isPointInMinimap`, `minimapPointToWorld`, `getTileMinimapColor`, `renderMinimap`) plus a stateful `Minimap` convenience class.
- **Default Geometry:** `160×160` px (`DEFAULT_MINIMAP_SIZE = 160`) placed in the `top-right` corner with `12` px margin (`DEFAULT_MINIMAP_MARGIN = 12`). Supports all four corners (`top-right`, `top-left`, `bottom-right`, `bottom-left`).
- **Color Priority & Batching:** `getTileMinimapColor` resolves `entity > non-depleted ore > terrain`. `renderMinimap` uses row-by-row horizontal run-length merging with `Math.floor`/`Math.ceil` pixel boundaries to eliminate subpixel seams (e.g., `160 / 64 = 2.5` px/tile) while keeping draw calls low and 100% deterministic.
- **Headless Compatibility:** Uses a structural `MinimapCanvasContext` interface (compatible with `CanvasRenderingContext2D` and headless mocks) with zero DOM imports.

## Edge Cases & Fail-Closed Guarantees
- **Viewport Box Clamping:** `computeCameraViewportBox` clamps the camera's visible world bounds to `[0, world.width] × [0, world.height]` so the viewport indicator never overflows the minimap frame; completely off-map cameras yield a zero-size box with zero `NaN`s.
- **Depleted Resources:** Resource nodes with `amount <= 0` fall back to the underlying terrain color.
- **Fail-Closed Validation:** Throws `MinimapError` (extending `SimulationError`) on non-positive viewport/size, negative margin, non-finite camera coordinates, `zoom <= 0`, or mismatched `world.tiles.length`.
- **Integration for T47/T50:** Call `renderMinimap(ctx, world, camera, viewport)` in the HUD pass; use `minimapPointToWorld(screenX, screenY, rect, worldBounds)` for click-to-pan minimap navigation.
