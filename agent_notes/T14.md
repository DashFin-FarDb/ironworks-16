# T14: Underground Belt (`src/logistics/undergroundBelt.ts`)

Implemented deterministic, headless entry/exit underground belt pairing, transit delay, and backpressure-safe item conservation.

## Constants & Geometry
- `UNDERGROUND_MAX_SPAN = 4` (max 4 underground gap tiles between entry and exit).
- `UNDERGROUND_MAX_DISTANCE = 5` (center-to-center tile distance in `1..5`).
- Transit delay: `computeTransitTicks(distance, speed = BELT_SPEED)` -> `Math.round(distance / speed)` ticks (`32` ticks/tile at `BELT_SPEED = 0.03125`, so max span of 4 gap tiles / distance 5 = `160` ticks).
- Per-lane tick spacing: `computeLaneTickSpacing(speed, spacing)` -> `8` ticks at default `BELT_SPEED = 0.03125` and `BELT_ITEM_SPACING = 0.25`.

## Key Design Choices for Downstream Tasks (T12, T39, T48)
- **In-Transit Storage:** Items in transit are stored in `entry.transitQueue` (`UndergroundBeltItem[]`) in FIFO order per lane (`'left' | 'right'`).
- **Pairing Rules:** `getUndergroundDistance` requires `entry.mode === 'input'`, `exit.mode === 'output'`, identical `direction`, strict axis alignment ahead of `entry`, and distance in `1..5`. `findMatchingUndergroundPair` stops scanning if an intervening same-direction, same-mode underground belt is encountered.
- **Zero-Loss Backpressure:** `advanceUndergroundBelt` uses the same `LaneHandoffFn` callback contract as `belt.ts`. Items only leave `transitQueue` when `handoff` returns `true`; otherwise they halt at `remainingTicks = 0` and trailing items on the same lane queue at `minTickSpacing` intervals. Unpaired belts reject insertion (`false`).
- **Fail-Closed Validation:** `createUndergroundBeltEntity` throws `InvalidPlacementError` for invalid modes; `insertIntoUndergroundBelt` validates `itemId` via `assertValidItemId` (`UnknownItemError`); `pairUndergroundBelts` and `computeTransitTicks` throw `SimulationError` on invalid inputs.
