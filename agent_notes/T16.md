# T16: Filter Inserter (`src/logistics/filterInserter.ts`)

Implemented the deterministic, headless, fail-closed filter inserter restricted to a whitelist of up to 3 canonical `ItemId`s (`MAX_FILTER_SLOTS = 3`), delegating state-machine transitions and world I/O to `T15` (`src/logistics/inserter.ts`).

## Key Design Choices
- **Reuse of T15 State Machine:** `stepFilterInserter` and `tickFilterInserter` compose the inserter's whitelist predicate with any optional `options.filter` and delegate directly to `stepInserter` / `tickInserter`. No state-machine or entity-routing logic is duplicated.
- **Fail-Closed Empty Whitelist:** When `inserter.filters.length === 0`, `isItemAllowedByFilter` returns `false` for all items so an unconfigured filter inserter picks nothing rather than acting as an unfiltered inserter.
- **Strict Validation & Deduplication:** `createFilterInserterEntity`, `setFilterInserterFilters`, and `addFilterInserterFilter` validate every `ItemId` via `assertValidItemId` (`UnknownItemError`), deduplicate entries while preserving order, and throw `SimulationError('FILTER_LIMIT_EXCEEDED', ...)` if more than 3 unique `ItemId`s are supplied. `createFilterPredicate` also re-validates `inserter.filters` on step/tick to catch external mutation.
- **Item Conservation on Filter Changes:** Modifying or clearing `filters` while `heldItem !== null` (e.g., mid-swing or during backpressure in `dropping`) still allows the held item to be dropped cleanly without loss or duplication.
- **Deterministic Batch Ticking:** `tickAllFilterInserters(world, options)` iterates `'filter_inserter'` entities in ascending numeric `EntityId` order.
