# T15: Inserter State Machine (`src/logistics/inserter.ts`)

Implemented the deterministic, headless, fail-closed inserter arm state machine (`idle -> picking -> swinging -> dropping -> returning -> idle`) moving 1 item at a time between source and target tiles.

## Key Design Choices
- **Coordinate Semantics:** `inserter.direction` points toward the target (drop) tile (`getInserterTargetCoord`); the source (pickup) tile is behind it (`oppositeDirection`, `getInserterSourceCoord`).
- **Exact Power-of-2 Timing:** Default phase durations are `INSERTER_PICK_TICKS = 4`, `INSERTER_SWING_TICKS = 16`, `INSERTER_DROP_TICKS = 4`, `INSERTER_RETURN_TICKS = 16` (`40` ticks/cycle = 1.5 items/sec at 60 TPS), with a `1 - 1e-9` completion threshold to prevent IEEE-754 rounding stalls on custom non-power-of-2 timings.
- **T16 Reuse Hook:** `AnyInserterEntity = InserterEntity | FilterInserterEntity`, `stepInserter`, and `tickInserter` accept an optional `filter?: (itemId: ItemId) => boolean` predicate so `T16` (`filterInserter.ts`) can reuse the state machine directly without duplicating transition or world-I/O logic.
- **Strict Item Conservation & Backpressure:** Items are only extracted on `picking` completion when `heldItem === null`. If the source empties mid-pick, the arm returns cleanly to `idle`. If the target is full/blocked on `dropping` completion, the arm halts in `dropping` (`phaseProgress = 1`, `active = false`) with `heldItem` preserved until space opens.
- **Entity Routing:** `tickInserter` / `dropIntoEntity` automatically routes fuel items (`isFuelItem`) to `fuelInventory` on `stone_furnace`, `burner_drill`, and `boiler`, non-fuel items to `inputInventory` on furnaces/assemblers/labs, and drops onto belts at offset `0.5` (far `right` lane first, falling back to `left`).
- **Arm Angle:** `computeInserterArmAngle` updates `armAngle` in radians deterministically every tick for `T40` (`entityLayer.ts`).
